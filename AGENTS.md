# Правила проекта aymakh

## Постоянные правила

- Отвечай владельцу по-русски и простыми словами. Перед изменениями сначала покажи план.
- Перед работой читай `D:\projects\обо мне.md` и изучай соответствующую часть кода.
- Ничего не удаляй без разрешения. Не заменяй и не переносить данные семейного дерева без проверенной копии и явного плана.
- Не придумывай факты; если решение зависит от отсутствующих требований, пометь предположение или задай вопрос.
- Не заявляй о проверке, сборке, миграции или восстановлении без фактического выполнения.
- После задачи сообщай выполненное, файлы, проверки, проблемы и следующий этап; обновляй `ROADMAP.md`.

## Архитектурные ограничения

- Сохраняй закрытый характер платформы. Не добавляй публичные профили/деревья/индексацию или глобальный каталог пользователей.
- Модульный монолит; процессы `web`, `api`, `worker`. Авторизация централизована в API.
- Каждая сущность семейных данных принадлежит `tree_id`; backend проверяет членство и роль на каждом пути доступа.
- RLS — второй барьер, а не замена API-проверке; пользовательский контекст задаётся только внутри транзакции.
- Не хранить генеалогические данные одним JSON-массивом как целевую модель. Люди, отношения, партнёрства, события, источники и медиа — отдельные сущности.
- Не допускать циклов родительских связей. Изменения имеют версии и optimistic locking.
- Закрытые файлы хранятся в приватном S3-совместимом хранилище и выдаются только после проверки прав через временную ссылку/поток.
- Поисковая индексация — через outbox; каждый результат ограничен разрешёнными деревьями.
- Изменения БД — только версионированными миграциями. Не хранить секреты в Git.
- Целевой стек описан в `ARCHITECTURE.md`; точные версии фиксируй на этапе 1 после проверки совместимости и актуальности.
- Redis подключай только при обоснованной необходимости. Выбор библиотеки визуализации дерева подтверждай сравнением на целевом графе.

## Skills

Перед созданием новых Skills проверь `D:\projects\.agents\skills\`, чтобы не дублировать их. В проекте созданы двенадцать специализированных Skills в `.agents/skills/`. Вызывай подходящий через `$architecture-expert`, `$genealogy-database`, `$family-tree-ui`, `$fullstack-development`, `$auth-security`, `$global-search`, `$media-storage`, `$realtime-collaboration`, `$ui-ux-design`, `$qa-automation`, `$devops-deployment` или `$backup-recovery`, когда он полезен для задачи. Поддерживай инструкции вместе с повторяемым процессом, не превращай их в общие заглушки.

## Проверки и команды

Текущая кодовая база — MVP на Node.js; в `package.json` сейчас есть только `start` и `create-owner`. Для текущего MVP:

```powershell
cd D:\projects\family-tree-vps
npm install
npm start
```

`npm install` допустим после согласования/начала этапа реализации: он обновит lock-файл, которого пока нет. Для будущего монорепозитория команды lint, typecheck, test и build должны быть добавлены на этапе 1 и перечислены здесь вместе с lock-файлом. Не выполнять тесты без запроса владельца или явного критерия этапа; требования приёмки продукта предусматривают тесты на соответствующих этапах.
