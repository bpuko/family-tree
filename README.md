# Семейное древо

Веб-версия исходного приложения с тем же редактором и видом дерева. Страница размещается на GitHub Pages; аккаунты и семейное древо хранятся отдельно в Supabase.

## Доступ и приватность

- Самостоятельной регистрации нет. Владелец выдаёт аккаунты из кнопки **Пригласить** в приложении.
- Только роль `owner` может приглашать родственников; серверная Edge Function проверяет эту роль перед отправкой приглашения.
- Данные дерева не находятся в GitHub и не доступны без входа в аккаунт семьи. Это обеспечивают политики RLS в `supabase/schema.sql`.
- Любой участник с аккаунтом может добавлять и редактировать записи людей в общем древе.
- Не публикуйте `service_role` или secret key. В `config.js` указывается только Project URL и publishable key.

## Подготовка Supabase

1. Создайте проект Supabase и скопируйте Project URL и publishable key в `config.js`.
2. В SQL Editor запустите весь файл `supabase/schema.sql`.
3. В Authentication настройте адрес сайта и redirect URL после смены пароля на URL GitHub Pages.
4. Отключите публичную регистрацию. Создайте аккаунт владельца через **Authentication → Users → Add user**.
5. Включите таблицу `family_state` в **Database → Publications → supabase_realtime**, чтобы древо обновлялось у вошедших родственников без перезагрузки.
6. Разверните функцию `supabase/functions/invite-member/index.ts` как Edge Function `invite-member`. Функция проверяет роль `owner` по JWT и только после этого отправляет приглашение и выдаёт роль `editor`.
7. Назначьте владельца в SQL Editor:

   ```sql
   insert into public.family_members (user_id, email, role)
   values ('UUID_ВЛАДЕЛЬЦА', 'EMAIL_ВЛАДЕЛЬЦА', 'owner');
   ```

После настройки владелец входит в сайт и нажимает **Пригласить**. Аккаунт автоматически получает роль `editor`. Чтобы отозвать доступ, владелец удаляет строку этого человека из `family_members` и отключает или удаляет его пользователя в Auth.

Для надёжной доставки приглашений настройте собственный SMTP в Supabase Auth. Стандартная почтовая отправка Supabase ограничена.

## GitHub Pages

Опубликуйте содержимое этой папки в отдельном GitHub-репозитории и в **Settings → Pages** выберите публикацию из ветки `main`, папки `/ (root)`. Семейные записи и учётные записи в репозиторий не добавляются. В Supabase укажите этот же Pages URL в разрешённых redirect URL для входа и восстановления пароля.

## Перенос уже созданного древа

В исходном приложении выберите **Сохранить**, чтобы выгрузить `.json`. После входа в новую веб-версию используйте **Открыть**, чтобы импортировать этот файл. После импорта изменения сохраняются в общем облачном древе.
